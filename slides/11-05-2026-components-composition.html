React Mental Model

Five ideas that need to connect

Component

A reusable UI building block with a clear responsibility.

Props

Input passed into a component so it can stay flexible.

State

Data that changes over time and should trigger a re-render.

Events

User actions like click, input or submit that can update state.

JSX is just the language we use to describe how these ideas show up on screen.

  • What repeats?
  • What changes from instance to instance?
  • What is just content, and what is behavior?

Decision Making

Component, prop, data or state?

Make it a component when...

  • It has a clear job.
  • It repeats in the UI.
  • It makes the parent easier to read.

Make it a prop when...

  • The structure stays the same.
  • Only labels, images or values change.
  • You want the same component in many contexts.

Keep it as data when...

  • It can be listed in an array.
  • You can map over it.
  • It does not change because of user interaction yet.

Use state when...

  • The value changes while the app runs.
  • A click or input should update the UI.
  • The user needs feedback from an action.
Props Example

One component, many posts

function PostCard({ username, caption, imageUrl, liked }) {
  return (
    <article className="post-card">
      <img src={imageUrl} alt="" />
      <h3>{username}</h3>
      <p>{caption}</p>
      <span>{liked ? "Liked" : "Not liked yet"}</span>
    </article>
  );
}

Why this matters

  • The structure stays stable.
  • The content changes through props.
  • The parent can reuse the same component for many posts.

Look for this pattern

If you copy-paste the same JSX and only change text or images, you probably want props.

State Example

Interaction needs state and events

function LikeButton() {
  const [liked, setLiked] = useState(false);

  return (
    <button onClick={() => setLiked(!liked)}>
      {liked ? "Unlike" : "Like"}
    </button>
  );
}
1

User clicks a button.

2

3

4

Composition Workflow

Suggested build order for Codeagram

1

Sketch the page zones: header, sidebar, feed, cards.

2

Build static components with placeholder content first.

3

Move repeated content into arrays and map over it.

4

Add props so the repeated parts can vary.

5

Add the smallest useful interactions with state.

6

Refactor names, files and reusable UI pieces afterward.

Component System

Small reusable pieces are enough

Useful reusable components

  • Button for actions and variants.
  • Card for consistent containers.
  • Tag for small labels or categories.

Common mistake

  • Making tiny components too early.
  • Splitting before the pattern is visible.
  • Creating generic components with unclear responsibility.

Practice Lens

When you get stuck, inspect the problem type

HTML / CSS issue?

The structure or styling is wrong, but the component idea still makes sense.

React issue?

Props are not passed, state is in the wrong place, or the event flow is unclear.

Composition issue?

The component boundaries are doing too much or not enough.

Data issue?

The content should probably live in an array and be rendered with map().
