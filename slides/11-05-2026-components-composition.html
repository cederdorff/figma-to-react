React Basics

Five ideas that need to connect

JSX

The syntax we use to describe what should appear on screen.

Components

Reusable UI building blocks with a clear job.

Props

Input that lets one component show different content.

State

Values that change over time and trigger a new render.

Events

Clicks, typing, submits, and other actions that update the UI.

Mental model

Structure first, then data flow, then interaction, then refactor.

React Basics

How the pieces fit together

function PostCard({ post }) {
  const [liked, setLiked] = useState(false);

  return (
    <article className="post-card">
      <h3>{post.username}</h3>
      <p>{post.caption}</p>
      <button onClick={() => setLiked(!liked)}>
        {liked ? "Unlike" : "Like"}
      </button>
    </article>
  );
}
1

Component: PostCard owns one clear piece of UI.

2

Props: post changes the content from card to card.

3

State: liked changes when the user interacts.

4

Event: the button click updates state and React re-renders.

Bridge to Codeagram

Think in components, not full pages

Read the UI before coding

  • What areas have different jobs?
  • What repeats?
  • What changes from post to post?
  • What needs interaction or feedback?

Useful first move

  • Start with the large layout zones.
  • Then identify repeated cards or items.
  • Then split out the smaller reusable pieces inside them.

What becomes data?

What becomes state?

  • Liked or bookmarked state.
  • Maybe selected tab or menu state later.

What becomes props?

  • Labels, images, counts, usernames and button variants.
Small Component System

Build a few reusable pieces from the app

Good candidates

  • Card for post and profile containers.
  • IconButton for small repeated actions.
  • Avatar for consistent profile images.
  • SectionTitle or Stat if the pattern is repeated.

What to avoid

  • Making everything reusable before the pattern is visible.
  • Creating abstract components with unclear names.
  • Splitting so much that the page becomes harder to read.

Small Component System

Suggested build order

1

Build the page layout with static placeholder content.

2

Turn repeated posts into a reusable PostCard.

3

Move post content into an array and render with map().

4

Add the smallest useful interaction with state and events.

5

Extract shared pieces like Avatar, IconButton, or Card.

6

Refactor names, props and files once the structure is working.
