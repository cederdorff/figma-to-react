React Basics

1. JSX

JSX is the syntax we use to describe what should appear on screen in React.

export default function App() {
  return (
    <main className="page-layout">
      <Navigation />
      <Header />
      <MainContent />
      <Footer />
    </main>
  );
}
function User({ name, mail, image }) {
  return (
    <div className="user-card">
      <img src={image} alt={name} />
      <h2>{name}</h2>
      <p>{mail}</p>
    </div>
  );
}

What to notice

  • It looks like HTML, but it is written inside JavaScript.
  • Capital names like Navigation mean React components.
  • Curly braces like {name} put JavaScript values into the UI.
  • Self-closing tags like <Navigation /> and <img /> are common in JSX.

Why it mattered in the exercise

JSX let the class describe both the page structure and the user card content before adding more logic.

React Basics

3. Props

Sometimes we pass one object prop and read values from that object inside the component. 

const mia = {
  name: "Mia",
  mail: "mia@example.com",
  image: "/mia.png"
};

const noah = {
  name: "Noah",
  mail: "noah@example.com",
  image: "/noah.png"
};

<User user={mia} />
<User user={noah} />
function User({ user }) {
  return (
    <div className="user-card">
      <img src={user.image} alt={user.name} />
      <h2>{user.name}</h2>
      <p>{user.mail}</p>
    </div>
  );
}

What to notice

  • The component receives one prop called user.
  • Inside the component, we use values like user.name and user.image.

When this is useful

If several values belong together, passing one object can make the component call cleaner.

Useful next step from: Getting started with React

React Basics

4. State

State is data that can change over time and cause React to render again.

Props come in. State changes inside the component.

const [liked, setLiked] = useState(false);

<button onClick={() => setLiked(!liked)}>
  {liked ? "Unlike" : "Like"}
</button>
const [users, setUsers] = useState([]);

useEffect(() => {
  async function fetchUsers() {
    const response = await fetch("...");
    const data = await response.json();
    setUsers(data);
  }

  fetchUsers();
}, []);

What to notice

  • liked starts as false.
  • When the button is clicked, setLiked changes the value.
  • The button text changes because React renders again with the new state.

Another state example you have seen

In the user exercise, users also started with one value and changed later when the fetch finished.

React Basics

5. Events

Events are how React responds to user actions like clicks, typing, and submits.

The event is the action. The state change is what happens after the action. 

function LikeButton() {
  const [liked, setLiked] = useState(false);

  return (
    <button onClick={() => setLiked(!liked)}>
      {liked ? "Unlike" : "Like"}
    </button>
  );
}

What to notice

  • onClick listens for the click.
  • When the user clicks, the function runs.
  • That function changes the state with setLiked.

Why this is a good event example

It is easy to see the full chain: click button, run code, change state, update the UI text.

How the pieces fit together

function PostCard({ username, image, caption }) {
  const [liked, setLiked] = useState(false);

  return (
    <article className="post-card">
      <img src={image} alt={username} />
      <h3>{username}</h3>
      <p>{caption}</p>
      <button onClick={() => setLiked(!liked)}>
        {liked ? "Unlike" : "Like"}
      </button>
    </article>
  );
}
1

JSX: tags and curly braces describe what should appear on screen.

2

Component: PostCard owns one clear piece of UI.

3

Props: username, image, and caption change the content.

4

State: liked remembers whether the post is liked or not.

5

Event: onClick runs when the button is clicked and updates the state.

Small Component System

Example 1: extract an Avatar component

export function UserInfo({ avatar, timestamp, username }) {
  return (
    <div className="user-info">
      <img className="avatar" src={avatar} />
      <h2>{username}</h2>
      <p>{timestamp}</p>
    </div>
  );
}
export function Avatar({ src, alt }) {
  return <img className="avatar" src={src} alt={alt} />;
}

export function UserInfo({ avatar, timestamp, username }) {
  return (
    <div className="user-info">
      <Avatar src={avatar} alt={username} />
      <h2>{username}</h2>
      <p>{timestamp}</p>
    </div>
  );
}

Why this is a good first extraction

  • The avatar already has one clear job: show a profile image.
  • The CSS is already isolated in one class: .avatar.
  • The component API stays small: src and alt.

What students should notice

We are not inventing a system from nothing. We are naming and extracting a pattern that already exists in the app.

export function IconButton({
  icon: Icon,
  label,
  active = false,
  hasDot = false,
  onClick
}) {
  return (
    <button
      className={`icon-button ${hasDot ? "has-dot" : ""}`.trim()}
      type="button"
      aria-label={label}
      onClick={onClick}
    >
      <Icon className={active ? "is-active" : ""} />
    </button>
  );
}

Why this helps

  • The button shape, spacing and icon behavior move into one place.
  • Different icons become props instead of copy-pasted markup.
  • Accessibility improves because aria-label becomes part of the API.

Small but useful API

icon, label, onClick, active and hasDot are enough for the current app. No need to over-design it yet.

Example 3: keep the system small

function App() {
  return (

        {posts.map(post => (
          <PostCard key={post.id} post={post} />

}
Small system for this app:

- Avatar
- IconButton
- maybe Card later

Keep PostCard as a feature component.
Do not split everything just because you can.

Good rule of thumb

  • Extract something when the pattern is repeated and has one clear purpose.
  • Keep feature components like PostCard intact while the app is still small.
  • Only add more system pieces when the next repetition appears in the code.

Suggested build order from the current app

  • Start with Avatar.
  • Then extract IconButton.
  • After that, decide whether Card or PostActions is actually needed.
