React Before MCP

Why React knowledge still matters

If you only prompt

  • You may get code you cannot explain.
  • You may keep duplicated or overly literal components.
  • You may miss where state and interaction should live.
  • You may accept a static screen instead of a prototype.

If you understand React

  • You can read the component structure critically.
  • You can decide what to keep, split, rename or rebuild.
  • You can place props, state and events more intentionally.
  • You can turn generated output into something more believable.
function PostCard({ post }) {
  const [liked, setLiked] = useState(false);

  return (
    <article>
      <h2>{post.username}</h2>
      <button onClick={() => setLiked(!liked)}>
        {liked ? "Liked" : "Like"}
      </button>
    </article>
  );
}
A Common Feeling

When the code works, but you cannot explain why

This is exactly why React knowledge matters today. If the output feels opaque, it becomes hard to validate, improve, or trust.

I know that we have only scratched the surface of React so far, but that is also what we have had time for. Even this level of knowledge helps you judge the output much better than if you had none at all.

MCP Basics

What is MCP?

MCP stands for Model Context Protocol. In short: it is a standard way for AI models (ChatGPT, Claude, and others) to connect to tools, apps, APIs, databases, and files.

Part 01
Example: Codex / ChatGPT

AI in VS Code

Understands your prompt and decides what tool context is needed.

→
Part 02
Example: Figma MCP

MCP Server

Acts as a bridge that exposes specific capabilities in a safe, structured way.

→
Part 03
Example: Figma

Tool Context

Returns real design data like nodes, spacing, components, and other metadata.

Instead of every AI app needing custom integrations for GitHub, Slack, databases, Figma, and more, MCP defines a common protocol so tools can plug into AI systems consistently.

MCP Basics

What MCP enables

An AI assistant can

  • read files
  • query databases
  • call APIs
  • interact with apps (GitHub, Notion, Figma, and more)
  • execute actions safely

What this means for class

  • Better context in, better first draft out.
  • Less manual copy-paste between tools.
  • You can focus more on decisions and quality.

Think "one protocol, many tools" instead of one-off integrations.

MCP Basics

Why do we need MCP?

Without MCP (prompt only)

  • The AI must guess layout and structure from text.
  • Important design details can be missed.
  • You often get output that feels generic.

With MCP (real tool context)

  • The AI can read actual design structure and properties.
  • Output is usually closer to the intended design.
  • You can spend more time improving instead of rebuilding basics.

Figma MCP Starter Guide

Exercise Checklist

What should you improve after generation?

Do not stop at the first draft. Read it through these three lenses.

Lens 01

Structure

Look at naming, repeated UI, and whether parts should become smaller components or props.

Is this component clear, or is it trying to do too much?
Lens 02

Interaction

Look for missing state, user feedback, and places where the prototype should react.

What should happen when a user clicks, types, or chooses?
Lens 03

Believability

Look at whether the flow feels understandable and whether the prototype should be rebuilt instead of patched.

If someone else tries it, will the flow make sense?

Pick one improvement first. Make it real before moving on.

MCP/AI helps you start faster. You still decide what makes the prototype good.
