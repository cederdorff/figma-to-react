Core idea

The webcam is only input after we interpret it.

The camera gives us images. The model gives us hand points. The interaction design decides what those points should mean.

hand input game state feedback

Mental model

The full pipeline

Understand the pipeline first, you do not need to read every line of code.

1

Camera frame

Browser webcam stream, usually through localhost and a permission prompt.

2

Hand landmarks

MediaPipe finds points such as wrist, thumb tip and index fingertip.

3

Gesture values

Rules interpret landmarks as values like pinch, grip, open hand or hand position.

4

Interaction state

React or game logic turns values into score, targets, balls, force or UI state.

5

Visible feedback

The screen shows what the system understood, and what changed because of it.

Code reading path

Open the projects through the same pipeline

When the code feels big, read it by responsibility instead of from top to bottom.

src/hooks/useHandTracking.js Starts/stops the camera, loads the model, runs the frame loop and passes data onward.
src/handTracking.js Creates the detector/landmarker and draws or converts hand landmarks.
src/gestures.js Interprets landmarks as gestures, positions, grip, wind or action states.
game logic files useCatchGame.js or game.js turns interaction values into rules and feedback.

Definition

What is MediaPipe?

What it is

MediaPipe is a real-time ML framework. In these projects, we use its hand model to detect and track hand landmarks in each webcam frame.

What it gives us

  • Landmark coordinates for key points on the hand.
  • Per-frame tracking data we can use in interaction logic.
  • Raw numeric output, not interaction meaning.
MediaPipe output -> landmark points (x, y, z) Our gesture rules -> pinch, open hand, pointing, grip, wind

Short version: MediaPipe tracks hands. Your code defines what those hand movements mean.

Interpretation

When can we say it interprets?

Camera captures

The webcam gives us video frames. It does not know what a hand, gesture or game action is.

Model tracks hand data

MediaPipe is a hand-tracking model. It outputs landmark coordinates (and confidence), not gesture meaning.

Code gives meaning

Our gesture logic turns tracked points into interaction states the prototype can act on.

tracked points -> gesture rules -> interaction meaning indexTip + thumbTip close together -> Pinch open fingers -> Open hand palm position -> Paddle

Interpretation happens when tracked points become meaningful interaction states.

What MediaPipe gives you

Landmarks are not gestures

  • A landmark is one tracked point on the hand.
  • MediaPipe gives numeric positions for those points on each frame.
  • The projects mostly use index tip, thumb tip, wrist and finger bases.
  • A gesture is a rule you write on top of those points.
pinchDistance = distance(indexTip, thumbTip) isPinching = grip > 0.6 isPointingUp = indexTip.y < wrist.y

In code

Interpretation happens in gestures.js

From landmarks to gesture values

webcam-ui/src/gestures.js 
const pinchDistance = getDistance(indexTip, thumbTip)
const grip = clamp(1 - (pinchDistance - 0.035) / 0.11, 0, 1)
const isPinching = grip > 0.6
const isPointingUp = indexTip.y < wrist.y
const openFingerCount = countOpenFingers(landmarks)

From values to a label

getGestureName(...) 
if (isPinching) return "Pinch"
if (openFingerCount >= 4) return "Open hand"
if (isPointingUp) return "Pointing up"

return "Tracking"

This is the pattern students can reuse: choose a few points, write a small rule, show feedback.

Exercise 1

Hand Puck

  • Best starting point for understanding the input pipeline.
  • The puck follows the index fingertip.
  • Pinch changes the puck scale and state.
  • The control panel is a debugging tool.
Hand Puck: tracking first, game rules later.

Hand Puck in code

The fingertip becomes CSS position

Map fingertip to stage coordinates

webcam-ui/src/gestures.js 
const targetX = 1 - clamp(gesture.indexTip.x, 0.03, 0.97)
const targetY = clamp(gesture.indexTip.y, 0.06, 0.94)

const nextX = currentX + (targetX - currentX) * 0.26
const nextY = currentY + (targetY - currentY) * 0.26

Show the interpretation on screen

movePuckWithGesture(...) 
puck.style.setProperty("--x", `${nextX * 100}%`)
puck.style.setProperty("--y", `${nextY * 100}%`)
puck.style.setProperty("--scale", String(0.96 + gesture.grip * 0.42))
puck.toggleAttribute("data-gripped", gesture.isPinching)

Hand Catch flow

What changes from Hand Puck?

Input still moves the puck

  • Index fingertip controls --x and --y.
  • Grip still changes the puck scale.
  • Tracking status still helps you debug.

Game loop reads the puck

  • Targets fall every animation frame.
  • The game checks distance between target and puck.
  • React updates score, streak, time and misses.
if (distance <= puck.radius + itemRadius) { score += 10 + streakBonus }

Hand Catch game loop

The game reads the puck position

Read the current puck as a circle

useCatchGame.js 
const x = Number(puck?.dataset.x)
const y = Number(puck?.dataset.y)
const size = (puck?.offsetWidth || 72) * scale

return {
  radius: size * 0.48,
  x: x * stageSize.width,
  y: y * stageSize.height
}

Catch is a distance check

isItemCaught(...) 
const distance = Math.hypot(itemX - puck.x, itemY - puck.y)

return distance <= puck.radius + itemRadius

This is why the visual puck matters: the same position becomes both feedback and game data.

Advanced path

Air Juggler V1

Starts from Hand Puck

The implementation guide adds one layer at a time, so students can see where each concept enters.

Gesture returns position

movePuckWithGesture returns { x, y } so physics can use the puck.

Pinch becomes action

The ball only gets hit when the player pinches near it, so gesture state matters.

This is the shift from moving an interface element to controlling a real-time system.

Air Juggler V1 in code

The gesture output feeds physics

The frame loop connects both systems

air-juggler-game/src/hooks/useHandTracking.js 
const gesture = getHandGesture(landmarks)
const puckPosition = movePuckWithGesture(gesture, puck)

const didUpdateScore = tickGame(
  gameRef.current,
  ball,
  puckPosition,
  gesture
)

Pinch near the ball becomes a hit

tickGame(...) 
const distance = Math.hypot(game.x - puck.x, game.y - puck.y)
const canHit = now - game.lastHitTime > 140

if (gesture.isPinching && distance < 0.12 && canHit) {
  game.score += 1
  game.vy = -Math.max(0.013, Math.abs(game.vy) * 0.9 + 0.005)
}

const palm = PALM_INDICES.map((index) => hand.keypoints[index])
const avgX = palm.reduce((sum, keypoint) => sum + keypoint.x, 0) / palm.length

Dandelion in code

Gesture values become interaction qualities

Convert gesture into force

dandelion-experiment/src/gestures.js 
interaction.force = clamp(
  0.16 + gesture.grip * 0.36 + gesture.wind * 0.44 + motionWind,
  0,
  1
)

interaction.isOpenHand = gesture.isOpenHand
interaction.isPinching = gesture.isPinching

The visual scene reads that force

DandelionField.jsx

Debugging

Check the pipeline one step at a time

Camera does not start Use the Vite localhost URL, allow permission, close other apps using the webcam.
No hand detected Improve lighting, keep the full hand visible, move slower, check model loading.
Gesture feels wrong Inspect landmark rules and thresholds in gestures.js.
Game does not react Check whether game logic is reading the same position or gesture value that the UI shows.
User is confused Add feedback: detected/not detected, active gesture, score change, hit effect or fallback controls.

Design questions

What makes it usable?

Reliability

Does the gesture work under normal lighting, distance and movement speed?

Feedback

Can the user see what the system recognized and what changed because of it?

Fallback

Can the prototype still be tested with pointer or keyboard input when tracking fails?

Exam project pattern

Borrow the structure, not the whole game

Make one interaction object

your-project/src/interaction.js 
const interaction = {
  position: gesture.indexTip,
  action: gesture.isPinching ? "select" : "hover",
  intensity: gesture.grip,
  confidence: tracking.confidence
}

Then connect it to your concept

examples 
museum object -> pinch to inspect
festival schedule -> open hand to reveal
product finder -> hand position to filter
installation -> motion speed to create force

The exam question is not only “does it work?” but “why is this input meaningful here?”

Use it in the exam project

Explain the choice, not only the effect

  • What user action does the webcam make possible?
  • Why is hand input better than click, tap or drag here?
  • Which data from the hand do you actually use?
  • How do you show recognition, uncertainty and result?
  • What would you test before calling it a finished interaction?
