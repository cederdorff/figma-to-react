This is meant as a clarifying wrap-up, not a full new lecture. The goal is to help students understand what the exercises are doing and where to look when they want to customize them.

Core idea

The webcam is only input after we interpret it.

The camera gives us images. The model gives us hand points. The interaction design decides what those points should mean.

hand input game state feedback

Mental model

The full pipeline

1

Camera frame

Browser webcam stream, usually through localhost and a permission prompt.

2

Hand landmarks

MediaPipe finds points such as wrist, thumb tip and index fingertip.

3

Gesture values

Rules interpret landmarks as values like pinch, grip, open hand or hand position.

4

Interaction state

React or game logic turns values into score, targets, balls, force or UI state.

5

Visible feedback

The screen shows what the system understood, and what changed because of it.

Interpretation

When can we say it interprets?

Camera captures

The webcam gives us video frames. It does not know what a hand, gesture or game action is.

Model detects

MediaPipe interprets the image enough to say: these pixels look like a hand with landmarks.

Code gives meaning

Our gesture logic turns tracked points into interaction states the prototype can act on.

tracked points -> gesture rules -> interaction meaning indexTip + thumbTip close together -> Pinch open fingers -> Open hand palm position -> Paddle

Interpretation happens when tracked points become meaningful interaction states.

What MediaPipe gives you

Landmarks are not gestures

  • A landmark is one tracked point on the hand.
  • The projects mostly use index tip, thumb tip, wrist and finger bases.
  • A gesture is a rule you write on top of those points.
pinchDistance = distance(indexTip, thumbTip) isPinching = grip > 0.6 isPointingUp = indexTip.y < wrist.y

What changes from Hand Puck?

Input still moves the puck

  • Index fingertip controls --x and --y.
  • Grip still changes the puck scale.
  • Tracking status still helps you debug.

Game loop reads the puck

  • Targets fall every animation frame.
  • The game checks distance between target and puck.
  • React updates score, streak, time and misses.
if (distance <= puck.radius + itemRadius) { score += 10 + streakBonus }

Advanced path

Air Juggler V1

Starts from Hand Puck

The implementation guide adds one layer at a time, so students can see where each concept enters.

Gesture returns position

movePuckWithGesture returns { x, y } so physics can use the puck.

Pinch becomes action

The ball only gets hit when the player pinches near it, so gesture state matters.

This is the shift from moving an interface element to controlling a real-time system.

Debugging

Check the pipeline one step at a time

Camera does not start Use the Vite localhost URL, allow permission, close other apps using the webcam.
No hand detected Improve lighting, keep the full hand visible, move slower, check model loading.
Gesture feels wrong Inspect landmark rules and thresholds in gestures.js.
Game does not react Check whether game logic is reading the same position or gesture value that the UI shows.
User is confused Add feedback: detected/not detected, active gesture, score change, hit effect or fallback controls.

Design questions

What makes it usable?

Reliability

Does the gesture work under normal lighting, distance and movement speed?

Feedback

Can the user see what the system recognized and what changed because of it?

Fallback

Can the prototype still be tested with pointer or keyboard input when tracking fails?

Use it in the exam project

Explain the choice, not only the effect

  • What user action does the webcam make possible?
  • Why is hand input better than click, tap or drag here?
  • Which data from the hand do you actually use?
  • How do you show recognition, uncertainty and result?
  • What would you test before calling it a finished interaction?
