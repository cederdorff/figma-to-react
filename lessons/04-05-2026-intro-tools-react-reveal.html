Two Terms We Will Use All the Time

Figma

Figma is where we read and organise the design: screens, layout, components, variants and user flows.

React

React is where we build the interface in code: components, props, state and interaction.

In short: Figma helps us see the structure and React helps us build the structure.

What Is an Interface?

An interface is the place where a person and a system meet.

What an interface does

  • Helps the user understand what is possible
  • Lets the user give input
  • Gives feedback
  • Moves the user through an experience

Conventional interfaces

Most interfaces we meet every day involve things such as:

  • screens and touchscreens
  • keyboard and mouse
  • sound and light

And on screens, we often use patterns such as:

  • buttons
  • menus
  • pages
  • links
  • forms
Start broad. An interface is not only a screen. It can be a button, a gesture, a sound, a physical object, camera input or motion response. The point here is to ground students in the idea that interface means input, feedback and flow, not just visuals.

Individual Exercise

Think of an interface you remember

Choose one familiar interface you have used yourself.

  • What was it?
  • What was the user trying to do?
  • How did the user give input?
  • What feedback did the interface give?
  • Did it feel useful, playful, confusing or surprising?

Write down a few notes. Start with something ordinary rather than trying to find a perfect example.

Let them begin with familiar interfaces. Most students will think of standard interfaces, and that is exactly what you want here. The goal is observation: input, feedback and user intention.

Short Input

What Is an Alternative Interface?

An alternative interface changes how input, feedback or interaction happens.

It might use

  • touch
  • drag
  • swipe
  • long press
  • movement
  • camera input
  • hand gestures
  • motion feedback

What makes it alternative?

It may move beyond the usual screen, mouse, keyboard and common UI patterns.

It might use the body, space, sensors, motion or the physical context around the user.

The real question

The point is not to be impressive. The point is to ask whether a different form of interaction would make more sense in a specific context.

Examples

Alternative Interfaces in Practice

Real examples

  • Webcam-controlled game: the camera tracks your movement and your body becomes the controller
  • Swipe and drag interfaces: interaction happens through movement rather than menus and forms
  • Motion-based feedback: animation, vibration or sound helps the user feel what changed
  • Touchless kiosks or installations: hand gestures or proximity can replace direct touch
Use the webcam-controlled game as the concrete anchor. Then broaden it: alternative interfaces can also be much smaller shifts, like gesture-driven navigation, motion feedback or touchless public interaction.

Examples

Alternative Interfaces in Practice

Dandelion installation

Can you blow dandelions with a hairdryer? In the installation Dandelion, you can.

  • The interface is not a button or a menu, but a physical object and a playful action
  • The user interacts through movement, air and a real-world metaphor
  • The digital response only makes sense because it is connected to the physical context
This is a strong example because it is intuitive and memorable. The user already understands the action from the physical world. The interface works by connecting that familiar action to a digital response.

Takeaway

User Interfaces Can Be Many Things

A user interface does not have to be just a screen, a button and a mouse.

It can also be

  • touch and gestures
  • movement and body position
  • camera input
  • sound, light or vibration
  • objects and physical actions

What matters

  • The interaction should fit the context
  • It should help the user understand what to do
  • It should make the experience clearer or more meaningful
This is the conclusion before the group exercise. The point is not to reject screens, buttons or mice. The point is to open up the idea of what an interface can be.

Bridge

From Interaction Ideas to Building

Once we have an interface idea, the next question is: how do we turn it into something we can actually build?

In design

  • We sketch screens, flows and interaction ideas
  • We decide what the user should see and do

In code

  • We structure the interface into smaller pieces
  • We make those pieces interactive and reusable
This is the pivot. Close the exercise by saying: we have talked about interaction and alternative interfaces, but now we need a way to build them. That way starts with structure.

We See UI as Components

We do not build interfaces as one big screen. We split them into components.

A component can be

  • a button
  • a card
  • a navigation bar
  • a product item
  • a modal or dialog

Why this matters

  • It makes the interface easier to understand
  • It makes the code easier to build and change
  • It helps us create reusable components across a design
  • It connects naturally to both Figma and React
This is an important teaching slide. Make the word component feel simple and practical. Students should leave with the idea that component thinking is a way of seeing interface structure.

Component Thinking

Components, Components, Components

How we read an interface

  • Start with the whole screen
  • Look for repeated UI patterns
  • Split the screen into smaller interface parts
  • Name those parts as components
  • Then decide what can change and what can become reusable components

This is one of the most important habits in the course: when we look at UI, we look for components.

Stay with the repetition here. The goal is to make component thinking feel like a reflex: see the whole, split it into parts, name the parts, then build from there.

Another Example

A Component Can Contain Components

Example: a media component

Think of components like LEGO bricks: larger pieces can be built from smaller pieces.

  • The whole thing can be one component
  • Inside it, we might have an image component
  • We might have a text component or text content area
  • We might have a button component
  • So a larger component can be built from smaller reusable components

This is the idea we keep returning to: components can contain other components.

Make the nesting idea explicit here. Students often understand components as single isolated things. This slide helps them see that a component can also be made of smaller parts.

Component Thinking

A Website Can Be a Component Tree

Example: homepage structure

  • Homepage can be the top-level component
  • It can contain Header, Article and Footer
  • Header can contain Logo, Title and Nav
  • Nav can contain individual Links

This is how we start seeing a page not just as one design, but as a hierarchy of reusable components and parts.

This is a good place to say the word tree out loud. Students do not need computer science depth here. They just need to see that pages are built from nested parts with parent-child relationships.

Real Example

Seeing Components on a Real Website

Even on a real homepage, we can start splitting the interface into larger sections and smaller reusable parts.

Keep this at a readable level. You do not need to identify every tiny element. The teaching point is that even a real homepage can be read as sections, actions, headings, text blocks and reusable UI parts.

Another Real Example

Instagram Feed as Components

Feed view

  • Sidebar navigation
  • Top story row / story items
  • Post card
  • Post media
  • Post actions: like, comment, share, save
  • Suggested users panel
  • Chat / message widget

Even a busy app feed is still built from reusable patterns: navigation, lists, cards, actions and widgets.

This is the app version of component thinking. You can point out that the post card itself is a component, and inside it there are smaller components such as avatar, username, media, actions and caption.

Profile view

  • Avatar
  • Name, bio and stats
  • Action buttons

React

A JavaScript library for building user interfaces

This is a simple reset slide before the React section starts. Let it breathe for a moment, then move straight into why React is useful in this course.

Why React?

React helps us build interfaces as pieces that can change.

It is useful for prototypes because it gives us:

  • components
  • reusable structure
  • state
  • event handling
  • interactive flows
Frame React as a prototyping material, not as full production engineering.

Thinking in React

React Mental Model

A component is a piece of interface.

Props are information passed into that piece.

State is information that can change.

Events are things the user does.

Keep this slide visible when live coding. It gives students four words to hang onto.

Component

A component is a reusable interface piece.

Examples:

  • button
  • card
  • navigation
  • filter
  • modal
  • product item
Connect this to Figma components. Students already understand repeated visual patterns.

JSX

JSX lets us write interface structure inside React.

It looks like HTML, but it belongs inside JavaScript.

function Button() {
  return <button>Save</button>;
}
Make the first example tiny. The point is recognition, not mastery.

Props

Props let the same component show different content.

function Button({ label }) {
  return <button>{label}</button>;
}
<Button label="Save" />
<Button label="Cancel" />
Compare props to component properties or text overrides in Figma.

State

State is what the interface remembers right now.

Examples:

  • selected item
  • open or closed
  • active step
  • liked or not liked
  • loading, success or error
This is where students start seeing why code can express more than a static design.

Event Handlers

Events connect user actions to changes in the interface.

function LikeButton() {
  const [liked, setLiked] = useState(false);

  return (
    <button onClick={() => setLiked(!liked)}>
      {liked ? "Liked" : "Like"}
    </button>
  );
}
This can be the first live-code pattern. A tiny state change is enough.
