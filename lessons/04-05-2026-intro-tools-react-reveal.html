Official Course Description

The elective Interactive design and development works with a wide range of technologies, focusing on the interaction between design and programming as well as alternative user interfaces. What Does the Curriculum Really Mean?

This elective is about how design and programming work together.

You will explore how technologies can be used to create interactive experiences, alternative interfaces and meaningful digital layers for real contexts.

  • Turning interface designs into working interactive prototypes
  • Using Figma and React to move from visual design to components, props, state, layout and interaction
  • Using MCP and AI-assisted workflows as support for translating, inspecting and improving code
  • Exploring alternative interfaces through gestures, motion feedback and experimental input
  • Working with real contexts and building meaningful digital layers for user experiences
  • Learning how to choose, test and explain your design and technology decisions
This now does both jobs: a student-friendly translation of the curriculum and a practical summary of what the course actually involves.

Not Just a Screen

A Figma frame is one moment.

A React prototype can show what happens:

  • before
  • during
  • after
  • when something goes wrong
  • when the user makes a choice
This is a key bridge. Design files often show static moments. Interactive prototypes need states, feedback and flow.

What Is an Interface?

An interface is the place where a person and a system meet.

It is how the user:

  • understands what is possible
  • gives input
  • receives feedback
  • moves through an experience
Keep this broad. An interface is not only a screen. It can be a button, a gesture, a sound, a physical object, a camera input or a motion response.

Discussion

Think of an interface you remember.

What made it interactive?

Was it useful, playful, confusing or surprising?

How could we build something like it?

Let students answer before showing technical explanations. The goal is to make them observe interaction quality, not just visual style.

What Is an Alternative Interface?

An interface does not have to be only buttons, menus and pages.

It can also use:

  • touch
  • drag
  • swipe
  • long press
  • movement
  • camera input
  • hand gestures
  • motion feedback
Now expand the definition. Alternative interfaces are not separate from UX; they are different ways of letting users understand, act and receive feedback.

What If the Interface Was Different?

Think of a normal digital action:

  • choosing something
  • navigating
  • confirming
  • exploring
  • getting feedback
  • saving something

Now ask: what if this did not happen through a normal button, menu or form?

Use this as an eye-opener. The point is not to make students chase impressive technology, but to make them question the default interface pattern. Ask whether it could happen through touch, gesture, movement, camera input or motion, and whether that would make the experience clearer, more meaningful or more memorable.

Pair Exercise

Choose a real context:

  • museum
  • shop
  • event
  • service
  • public space
  • product
  • company

Then define the user action, the normal interface, the alternative interface and why it makes sense.

Give them 5 minutes in pairs. Ask 2-3 pairs to share. End by asking: is the alternative interface meaningful, or is it just decoration?

Design to Code

When we move from Figma to React, we ask:

  • What are the repeated UI elements?
  • What should become a component?
  • What can change?
  • What should the user be able to do?
  • What feedback should the interface give?
This prepares the mental model for components, props, state and events.

Where MCP and AI Fit

MCP and AI can help us inspect, translate and scaffold from Figma.

But we still need to understand:

  • what the code does
  • what should be refactored
  • what interaction is missing
  • whether the prototype supports the concept
Set expectations early. AI assistance is part of the workflow later, but React understanding is what lets students judge and improve the output.

Why React?

React helps us build interfaces as pieces that can change.

It is useful for prototypes because it gives us:

  • components
  • reusable structure
  • state
  • event handling
  • interactive flows
Frame React as a prototyping material, not as full production engineering.

React Mental Model

A component is a piece of interface.

Props are information passed into that piece.

State is information that can change.

Events are things the user does.

Keep this slide visible when live coding. It gives students four words to hang onto.

Component

A component is a reusable interface piece.

Examples:

  • button
  • card
  • navigation
  • filter
  • modal
  • product item
Connect this to Figma components. Students already understand repeated visual patterns.

JSX

JSX lets us write interface structure inside React.

It looks like HTML, but it belongs inside JavaScript.

function Button() {
  return <button>Save</button>;
}
Make the first example tiny. The point is recognition, not mastery.

Props

Props let the same component show different content.

function Button({ label }) {
  return <button>{label}</button>;
}
<Button label="Save" />
<Button label="Cancel" />
Compare props to component properties or text overrides in Figma.

State

State is what the interface remembers right now.

Examples:

  • selected item
  • open or closed
  • active step
  • liked or not liked
  • loading, success or error
This is where students start seeing why code can express more than a static design.

Event Handlers

Events connect user actions to changes in the interface.

function LikeButton() {
  const [liked, setLiked] = useState(false);

  return (
    <button onClick={() => setLiked(!liked)}>
      {liked ? "Liked" : "Like"}
    </button>
  );
}
This can be the first live-code pattern. A tiny state change is enough.

First Build

Build a small interactive UI element.

It should include:

  • one component
  • one prop
  • one state value
  • one user action

Examples: like button, expandable card, selected filter, simple tab switcher.

Let students choose from the examples. Choice makes the exercise feel less like typing practice.

Tool Setup

We need the basics working:

  • browser
  • code editor
  • Node.js
  • npm
  • GitHub account
  • Figma account
  • React project
Treat setup issues as normal. The success criterion is that everyone knows what is missing and what to fix.

Checkpoint

Can you:

  • open the project?
  • start the local server?
  • change text in a component?
  • see the browser update?
  • explain where the component lives?
This gives a concrete minimum for the day. It also helps students who are unsure whether they are following.
